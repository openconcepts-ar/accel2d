# Navigating the RGB to eDP conversion Maze

The project originally selected NewCoSemi ICs since they're capable of RGB to eDP conversion, not too difficult to source, cheap, and easy to solder (QFN package) but now a two-chip solution is considered to avoid the problems  described below.

Olimex discarded the NewCoSemi ICs after [unsuccesful attemps](https://olimex.wordpress.com/2016/08/31/teres-i-diy-open-source-hardware-hackers-laptop-update) to make them work, as cause of lack willingess of the manufacurer to provide full documentation. They choose [Analogix ANX6345](https://lwn.net/Articles/794375/), but the chip is currently discontinued.

Thinkad laptop modders use boards based on NewCoSemi ICs, and they were able to [reverse enginner](https://web.archive.org/web/20260210185204/https://forum.thinkpads.com/viewtopic.php?t=126294&start=150) the register values set by yhe board MCU (sniffing the I2C channel), but the data doesn't match the known register maps and so the supported resolutions are just [HD and FHD](https://www.collegesidekick.com/study-docs/7007360), severely restricting the possible displays, which is a too big limitation for this project. Making the NewCoSemi ICs work at many resolutions would be higly valuable, but this calls for a significant reverse engineering effort.

In the case of the [NNT reform laptop](https://mntre.com/media/reform_md/2022-09-29-rkx7-showcase.html), a project supported by Nlnet, they followed a similar route as Olimex and used the a more modern version of the Analogix Ics: the [ANX9807](https://www.analogix.com/en/input/24bpp) to interface with their FPGA board, wich required [patching](https://source.mnt.re/reform/reform-kintex-som/-/blob/main/patches/linux/anx6345-hack-for-rkx7-with-anx9807.patch?ref_type=heads) [the ANX6345 linux drivers. But the IC is BGA, too expensive at about $13.72, and difficult to source from a reliable supplier (unreliable suppliers usually scrap them from junk boards).

Note that if the solution if too expensive, it calls for a different design like using a two-chip solution for first converting the RGB signals to DVI/HDMI or [FPD-Link](https://en.wikipedia.org/wiki/FPD-Link), then to eDP. This project is currently testing the first route based on the [TFP410 DVI transmitter](https://www.ti.com/product/TFP410) by Texas Instruments and [off-the-shelf boards](https://hackaday.io/project/179868/logs) based on REALTEK ICs (RTD2130e or RTD2556), them integrating it in a new board eDP adapter board (RTD2556 costs about $6 at [LCSC](https://www.lcsc.com/product-detail/C5358192.html)).

The design option which instead of using parallel RGB inputs, converts from FPD-Link (LVDS) to eDP like with the [LT8911 ICs](https://github.com/aystshen/lontium_lt8911_driver) is currently discarded: besides it would allow using a single IC, keeping the wide 24-bit input allows signalling to be limited to 148.5mbps per pin (at 1080p) which is within the capabilties of the current FPGA board and other planned boards. Serialized LVDS signalling requires a 7X data rate, which pushes the fmax too much, and so does not allow using simple hardware at the generation end (i.e a MCU driving smaller displays like 7" ones at 800x480).
